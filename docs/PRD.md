# 1 מטרת המוצר והמשתמשים

## הבעיה והערך

מפתח או אנליסט שמקבל טבלת פיצ׳רים ותיוגים צריך לזהות דגימות שכדאי לבדוק, להבין מדוע הן עלו לבדיקה ולהבדיל בין כמה סוגי ממצאים. דגימה עשויה להתאים בעיקר לקטגוריה אחרת; היא עשויה להימצא באזור שבו כמה קטגוריות מעורבות; ולעיתים חסרות ראיות כדי להסיק מסקנה. המוצר יחזיר ממצאים לכל דגימה ויאפשר לחקור אותם בקוד ובממשק.

הממצאים הם עדויות ביחס לפיצ׳רים, לייצוג, לשיטה ולסקאלת הניתוח שנבחרו. הם אינם קביעה ודאית שהתיוג שגוי או הוכחה שאף מסווג לא יוכל להפריד בין הקטגוריות. התאמה לקטגוריה חלופית וחפיפה עשויות להופיע יחד.

## המשתמשים המרכזיים

- מפתח אלגוריתמים עובד מתוך Python, Notebook או תהליך עיבוד קיים. הוא מגדיר רכיבים ופרמטרים בקוד ומקבל תוצאות נגישות לעיבוד נוסף.
- אנליסט עובד דרך UI, מעלה CSV או Excel, בוחר עמודות והגדרות, מריץ אנליזה, בוחן ממצאים ומייצא תוצאות.
- מפתח הרחבות מוסיף טרנספורמציה, מרחק, אנליזה או כלל החלטה. הוא כותב את המתמטיקה בפייתון רגיל ומסתמך על התשתית לצורך יצירת שדות והצגת תוצאות.

## היקף הגרסה הראשונה

הגרסה הראשונה כוללת סטנדרטיזציה, PCA עם בחירת רכיבים ו־whitening, מרחק אוקלידי, אנליזת שכנים ואנליזת OOF, מנגנון הרחבות, UI מקומי, טעינת CSV ו־Excel גם בספרייה וגם ב־UI, ייצוא CSV ושמירה ופתיחה של ריצה שלמה. Autoencoder יהיה רכיב אופציונלי שמותקן עם תוספת תלות נפרדת ונשאר כפוף לאותו חוזה ייצוג.

המוצר יקבל מספר שרירותי של פיצ׳רים מספריים ושמות עמודות ללא הנחות על תחום היישום. מקורות הקלט החיצוניים הנתמכים בגרסה הראשונה הם קובצי CSV ו־Excel בלבד. קריאה ממסדי נתונים, לרבות SQL, ופורמטי קלט נוספים נדחים לשלב עתידי של המוצר, הן בספרייה והן ב־UI. לא ייכללו כעת מחברי מסד נתונים, פרטי חיבור או שדות שאילתה. שרת מרובה משתמשים ונתונים גולמיים כגון תמונות או סדרות באורך משתנה אינם דרישה לגרסה הראשונה.

# 3 חוזה הנתונים

## מקורות קלט ומבני עבודה

CSV ו־Excel הם מסלולי טעינת הנתונים של המוצר. התמיכה ב־Excel כוללת קובצי `.xlsx` ו־`.xls`. הספרייה תספק פונקציות ייבוא ציבוריות שמחזירות pandas.DataFrame רגיל; ה־UI יפעיל את אותן פונקציות. משתמש בקוד לא יידרש לקרוא את הקובץ בעצמו באמצעות pandas או להפעיל UI.

DataFrame, Series ו־NumPy הם מבני העבודה בזיכרון של ה־API החישובי. אפשר להמשיך להעביר אליו נתונים שכבר קיימים בזיכרון, כפי שמוגדר להלן. אפשרות זו אינה מוסיפה מסלול טעינה מובנה ממסד נתונים או מפורמט קובץ אחר. קובץ `.audit.zip` משמש לפתיחה חוזרת של ריצה שמורה, בנפרד מייבוא נתוני מקור.

## הקלט הציבורי

| שדה | טיפוס עיקרי | חובה | משמעות |
|---|---|---|---|
| X | pandas.DataFrame | כן | שורה לדגימה ועמודה לכל פיצ׳ר שנבחר |
| y | pandas.Series | כן לשיטות הראשונות | תיוג יחיד לכל דגימה |
| groups | pandas.Series | לא | שיוך להקלטה או לקבוצה של דגימות תלויות |
| metadata | pandas.DataFrame | לא | שדות לתצוגה ולסינון שאינם פיצ׳רים כברירת מחדל |
| sample_id | אינדקס ייחודי | כן פנימית | זהות הדגימה בכל שלבי המערכת |
| feature_names | שמות העמודות | כן פנימית | שמות הפיצ׳רים וסדרם |

ה־API יתמוך גם ב־NumPy arrays בגודל דו־ממדי עבור X ובווקטור חד־ממדי עבור y. במסלול זה ניתן להעביר `sample_ids` ו־`feature_names`; בהיעדרם ייווצרו מזהים ושמות דטרמיניסטיים לפי סדר הקלט. מזהים שנוצרו כך תקפים בתוך snapshot הנתונים, והשוואת ריצות אחרי שינוי סדר מחייבת מזהים מקוריים.

במסלול pandas האינדקסים של X, y, groups ו־metadata חייבים להיות זהים ובאותו סדר. אי התאמה מחזירה שגיאה; הספרייה אינה מבצעת join או סידור מחדש באופן סמוי. המזהים יכולים להיות מחרוזות או מספרים, חייבים להיות ייחודיים וללא ערכים חסרים.

## אימות והכנת נתונים

הפיצ׳רים בגרסה הראשונה חייבים להיות מספריים וסופיים לאחר preprocessing. תיוג חסר, מזהה כפול, שמות פיצ׳רים כפולים וסתירה בין מספר השורות מחזירים שגיאה שמציינת את השדה והדגימות הרלוונטיות. ערכים חסרים יידחו כברירת מחדל. אם נבחר רכיב השלמת חוסרים, הוא יילמד מנתוני הייחוס המתאימים בלבד.

בחירת הפיצ׳רים מפורשת. עמודות תיוג, מזהים ו־metadata אינן נכנסות אוטומטית למתמטיקה. נתוני המקור אינם משתנים על ידי הריצה. לכל ריצה נוצר snapshot עקבי של השדות שנצרכו, או אובייקט נתונים בעל בעלות פנימית שמונע משינוי בקלט המקורי לשנות תוצאה קיימת.

groups ישמש לחלוקה קבוצתית ב־OOF. בשיטת השכנים תהיה בחירה עצמאית אם להחריג גם דגימות מאותה קבוצה. מטרת groups והמדיניות שהופעלה יוצגו בהגדרות הריצה.

# 4 חוויית השימוש מתוך פייתון

## ממשק רגיל של ספרייה

כל הגדרה ניתנת להעברה באמצעות ארגומנטים ואובייקטים בפייתון. אין צורך ליצור קובץ JSON או לערוך קובץ קונפיגורציה. רכיבים מובנים יקבלו constructors עם חתימות מפורשות, type hints ו־docstrings קצרים. ה־API הציבורי ישמור על אותם שמות ומשמעויות בכל גרסת schema.

הדוגמה טוענת קובץ באמצעות הספרייה ומעבירה את העמודות שנבחרו לאנליזה:

```python
from data_audit import (
    audit, load_csv, PCAEmbedding, NeighborAudit,
    OOFAudit, ReviewPolicy
)
from sklearn.linear_model import LogisticRegression

feature_columns = [f"feature_{i}" for i in range(1, 13)]
df = load_csv("samples.csv", id_column="sample_id")

result = audit(
    X=df[feature_columns],
    y=df["label"],
    groups=df["recording_id"],
    metadata=df[["recording_id", "sensor_id"]],
    embedding=PCAEmbedding(
        n_components=8, standardize=True, whiten=True
    ),
    methods=[
        NeighborAudit(
            name="neighbors", n_neighbors=30,
            min_neighbors=10, radius_mode="auto"
        ),
        OOFAudit(
            name="oof",
            estimator=LogisticRegression(max_iter=1000),
            n_splits=5, n_repeats=3, random_state=42
        ),
    ],
)
```

לאחר ההרצה ניתן למיין את התוצאות ולהפעיל מדיניות החלטה בנפרד:

```python
nn = result.samples.query("method_id == 'neighbors'")
ranked = nn.sort_values("label_issue_score", ascending=False)
review = result.apply_policy(
    method_id="neighbors",
    policy=ReviewPolicy(
        issue_threshold=0.5, overlap_threshold=0.6,
        require_support=True
    ),
)
```

`audit` מחזיר AuditResult. הקריאה `apply_policy` מחזירה DecisionResult חדש עם מדיניות ודגלים, בלי לשנות את ציוני האנליזה. הערכים המספריים בדוגמה הם preset פתיחה לצורך סקירה, ומחייבים בחינה וכיול לפי הדאטה לפני שימוש כהחלטה תפעולית. בחירת שמונה רכיבים תקפה רק כשהממדים וגודל קבוצת האימון מאפשרים זאת.

לכל שיטה מזהה מופע ייחודי. אפשר להריץ את אותה שיטה פעמיים עם פרמטרים שונים ושמות שונים. לכל ריצה recipe אחד של ייצוג; השוואת ייצוגים נעשית בין ריצות נפרדות על אותו snapshot.

## ייבוא קבצים מתוך הספרייה

לייבוא Excel משתמשים באותו מסלול המשך, ומחליפים רק את קריאת הקובץ:

```python
from data_audit import load_excel, list_excel_sheets

sheets = list_excel_sheets("samples.xlsx")
df = load_excel(
    "samples.xlsx", sheet_name=sheets[0],
    id_column="sample_id",
)
```

בחירת `sheets[0]` בדוגמה היא בחירה מפורשת של המשתמש בקוד. שמות הגיליונות זמינים לבחירה אחרת; אין איחוד אוטומטי של גיליונות.

| פונקציה ציבורית | פרמטרים עיקריים | תוצאה והתנהגות |
|---|---|---|
| load_csv | source, id_column=None, delimiter=",", encoding="utf-8-sig", header=0, dtype=None | DataFrame מקובץ CSV עם אימות מבנה ומזהים |
| list_excel_sheets | source | רשימת שמות הגיליונות לפי סדרם בקובץ |
| load_excel | source, sheet_name=None, id_column=None, header=0, dtype=None | DataFrame מגיליון Excel יחיד עם אותו אימות |

`source` הוא נתיב מקומי מסוג str או Path, או אובייקט קובץ בינרי שניתן לקריאה ול־seek, כדי לאפשר שימוש באותו קורא גם בהעלאה דרך UI. יתר הפרמטרים מועברים כארגומנטים בעלי שם. `header` הוא מספר שורת הכותרת החל מאפס. `dtype` הוא מיפוי אופציונלי של שמות עמודות לטיפוסים; גם הגדרה זו נעשית בקוד רגיל.

כשנבחר `id_column`, הקורא טוען אותה תוך שמירת המזהים הטקסטואליים, בודק ייחודיות וחוסרים ומגדיר אותה כאינדקס. בהיעדרה נוצרים מזהי דגימה דטרמיניסטיים לפי סדר השורות, שתקפים בתוך snapshot הקובץ; השוואה אחרי שינוי סדר דורשת מזהים מקוריים. בחירת פיצ׳רים, תיוגים, groups ו־metadata נעשית לאחר הטעינה, וה־API החישובי מבצע את אימות התפקידים המתואר בסעיף 3. הקורא אינו מריץ אנליזה או משנה תיוגים.

אם `sheet_name` לא ניתן ויש גיליון יחיד, הוא נבחר אוטומטית. אם יש כמה גיליונות, מוחזרת שגיאה עם שמותיהם ודרישה לבחירה מפורשת. שם גיליון לא קיים או פורמט לא נתמך מחזירים הודעה ממוקדת. התנהגות זו היא חוזה הספרייה, גם אם קורא ה־pandas שמתחתיה מציע אפשרויות נוספות.

## שימוש ברכיב מותאם מתוך קוד

כתיבת הרחבה אינה מחייבת כתיבת מחלקת קונפיגורציה או wrapper עבור ה־UI. התשתית מספקת פעולת binding שמקבלת פונקציה ואת הפרמטרים שלה ומייצרת רכיב תקין:

```python
from data_audit import bind_embedding, bind_method, bind_policy

embedding = bind_embedding(fit_custom, epsilon=1e-6)
method = bind_method(analyze_custom, name="custom", window=20)
policy = bind_policy(decide_custom, threshold=0.7)
```

ה־binding בודק את שמות הארגומנטים והטיפוסים באמצעות אותה חתימה שממנה נבנה הטופס. הוא אינו מפעיל UI ואינו דורש העתקת הפונקציה לתיקיית הרחבות. המסלול המובנה מספק נוחות שימוש כשל ספרייה מוכרת; המסלול המותאם נשאר פונקציה רגילה עם מעט קוד חיבור.

# 5 חוזה ההרחבות והפקת השדות

## סוגי ההרחבות

| סוג | פונקציית כניסה | קלט שמספקת התשתית | תוצאה מינימלית |
|---|---|---|---|
| ייצוג או נרמול | fit | X של נתוני האימון | פונקציית transform או אובייקט עם transform |
| מרחק | distance | שני וקטורים a ו־b | מספר סופי ואי שלילי |
| אנליזה | analyze | AnalysisInput | mapping של טבלאות תוצאה |
| מדיניות החלטה | decide | טבלת ממצאים של שיטה אחת | DataFrame של דגלים לפי sample_id |

קלטי התשתית אינם שדות בטופס. כל הפרמטרים הנוספים בחתימה הם הגדרות משתמש. אין לסרוק פונקציות עזר או imports כנקודות כניסה נוספות. מחלקות מובנות ופונקציות מותאמות משתמשות באותו adapter פנימי; אין שתי מערכות הרצה שונות.

AnalysisInput הוא אובייקט קריאה בלבד עם X כמטריצת NumPy, y, sample_ids, feature_names, groups, metadata וגישה ל־recipe של הייצוג והמרחק. הפעולה `fit_embedding(train_indices)` מחזירה מיפוי שנלמד רק על האינדקסים שסופקו. הייצוג אינו מחליף את X הגולמי בתוך הקלט, כדי ששיטה מבוססת folds תוכל לשלוט נכון ב־fit.

## דוגמה לנרמול מותאם

הקובץ הבא הוא הרחבה מלאה, ללא import של הספרייה או של ה־UI:

```python
import numpy as np

def fit(X, epsilon=1e-8):
    """Standardize features using the reference data."""
    if epsilon <= 0:
        raise ValueError("epsilon must be positive")
    mean = X.mean(axis=0)
    scale = np.maximum(X.std(axis=0), epsilon)

    def transform(X_new):
        return (X_new - mean) / scale

    return transform
```

ה־transform שומר את מספר השורות ואת סדרן ומחזיר מטריצה סופית בעלת מספר עמודות עקבי. מותר לשנות את מספר העמודות. כאשר שמות פיצ׳רים חדשים אינם מסופקים, התשתית מייצרת שמות z0, z1 וכן הלאה. רכיבי ייצוג ניתנים להרכבה כרצף; כל רכיב נלמד רק לאחר שהרכיבים הקודמים נלמדו על אותו סט אימון.

## דוגמה למדיניות סף מותאמת

```python
import pandas as pd

def decide(samples, threshold=0.7):
    if not 0 <= threshold <= 1:
        raise ValueError("threshold must be between 0 and 1")
    flags = samples["label_issue_score"].ge(threshold)
    flags = flags.astype("boolean")
    valid = samples["sufficient_support"].fillna(False)
    flags = flags.where(valid, pd.NA)
    return pd.DataFrame({"label_issue": flags}, index=samples.index)
```

טבלת הקלט למדיניות מכילה אינדקס sample_id ייחודי, ציונים ומדדים מספריים של אותה שיטה. ניתן להצמיד אליה diagnostics נבחרים באמצעות ה־API. המדיניות מחזירה אותם מזהים, עם עמודות דגלים מסוג nullable boolean. ערך חסר מבטא הימנעות מהכרעה, ו־False מבטא בדיקה שלא עברה את הסף.

ב־UI המשתמש מפעיל תיקיית הרחבות מוכרת. המוסכמה היא קובץ אחד לכל רכיב תחת embeddings, distances, methods או policies, עם פונקציית הכניסה שבטבלה. שם הקובץ הוא שם ברירת המחדל, וה־docstring הוא תיאור קצר. אין צורך ב־decorator, רישום ידני בטופס או קובץ schema.

הגילוי ואימות החתימה נמצאים בספרייה. פעולת רענון תציג רכיבים חדשים ושגיאות טעינה לפי קובץ. שינוי בקובץ שכבר משתתף בריצה ייכנס לתוקף בריצה הבאה, עם גרסה או hash חדש. נתוני CSV ו־Excel אינם משמשים מקור להרחבות קוד.

לשיטה חדשה מספיק להחזיר mapping עם `samples` כ־DataFrame. אפשר להוסיף `class_evidence`, `diagnostics` ו־`evidence` כמיפוי שמות לטבלאות. אין חובה לייבא מחלקת תוצאה של הספרייה. התשתית מאמתת מזהים, סוגי עמודות וטווחי ציונים. שדות סטנדרטיים שהשיטה אינה מפיקה מסומנים כלא נתמכים; הם אינם ממולאים באפס. כותב השיטה אינו מוסיף method_id לכל שורה: התשתית מצמידה אותו ממזהה המופע.

לדוגמה, שיטה שמחזירה מדד מרחק מן המרכז יכולה להיכתב כך. זהו מדד כללי, שאינו מוגדר אוטומטית כחשד לתיוג שגוי:

```python
import numpy as np
import pandas as pd

def analyze(data, power=2.0):
    if power <= 0:
        raise ValueError("power must be positive")
    transform = data.fit_embedding(np.arange(len(data.X)))
    Z = transform(data.X)
    score = np.linalg.norm(Z - Z.mean(axis=0), axis=1) ** power
    samples = pd.DataFrame({
        "sample_id": data.sample_ids,
        "distance_from_center": score,
    })
    return {"samples": samples}
```

עמודות נוספות של שיטה נשמרות עם namespace של השיטה וזמינות בטבלה ובמדיניות החלטה. ניתן לספק תיאור ציון קצר עם טווח וכיוון באמצעות descriptor אופציונלי. היעדר descriptor אינו מונע הצגת הערך, אך אינו מאפשר לפרש אותו כציון סטנדרטי.

# 6 ייצוגים ומרחקים

## רכיבים מובנים

- Identity מעביר את הפיצ׳רים כפי שהם.
- Standardize לומד ממוצע וסקאלה מכל פיצ׳ר ומגן מפני שונות זעירה באמצעות epsilon חיובי.

PCA מלא עם whitening וללא רגולריזציה, ולאחריו מרחק אוקלידי, שקול למרחק מהלנוביס לפי אותה מטריצת covariance כשהיא הפיכה. השמטת רכיבים או רגולריזציה משנה את המרחק הזה. PCA ו־whitening אינם מסירים תלות לא לינארית כללית. Autoencoder יכול ללמוד מבנה לא לינארי, אך אין הנחה שהמרחב שלו מסודר סמנטית ללא בדיקה.

## למידה והפעלה

כל fit מחזיר מצב עצמאי. ב־OOF, הסטנדרטיזציה, PCA, השלמת החוסרים ו־autoencoder נלמדים מחדש בכל fold על חלק האימון בלבד. גם validation לצורך early stopping נמצא בתוך חלק האימון. בהפעלת transform אין fit נוסף. בנתונים חדשים נבדקים מספר העמודות ושמותיהן לפני שימוש במיפוי שנלמד.

## מרחק כרכיב עצמאי

מרחק אוקלידי יהיה ברירת המחדל בשיטת השכנים. ניתן להעביר פונקציית מרחק מותאמת. המרחק מחזיר dissimilarity בלבד; רדיוס, בחירת שכנים וכללי החלטה נמצאים בשיטה ובמדיניות.

לא כל dissimilarity מקיימת את כל אקסיומות המטריקה. האצה באמצעות אינדקס תחול רק כאשר הרכיב והאלגוריתם תומכים בה. תמיד יהיה מסלול חישוב מדויק וכללי עבור callable מתאים. אין לבנות מטריצת מרחקים מלאה כברירת מחדל.

# 7 שיטות האנליזה הראשונות

## אנליזת שכנים

השיטה לומדת ייצוג על snapshot הייחוס ומחפשת שכנים לכל דגימה. היא מחריגה את הדגימה לפי sample_id, גם אם קיימות דגימות אחרות בעלות פיצ׳רים זהים. אפשר להחריג קבוצה שלמה באמצעות פרמטר ייעודי.

תחילה נאספות עד n_neighbors דגימות קרובות, ואז מוחל רדיוס כאשר הוגדר. מספר השכנים המשמש להכרעה הוא המספר שנשאר לאחר ההחרגות והסינון. השיטה מחזירה את התפלגות התיוגים המשוקללת, ציונים, מדדי תמיכה וטבלת שכנים.

| n_neighbors | 30 | מספר שכנים מרבי |
| weighting | uniform | שקלול אחיד או inverse_distance |
| radius_mode | auto | auto, fixed או none |

הרדיוס האוטומטי יכויל מן התפלגות מרחקי השכן ה־k בנתוני הייחוס, לאחר החרגת עצמי והחרגות קבוצתיות שנבחרו. הערך המכויל יישמר ויוצג. זהו כיול סקאלה, שאינו מהווה כיול הסתברות או הוכחה לייצוגיות. אם אין די דגימות לכיול, מוחזרת שגיאה ברורה או נדרשת בחירה מפורשת במצב none; אין מעבר סמוי בין המצבים.

כאשר אין רדיוס, התמיכה המספרית מבוססת על כמות וריכוז משקל בלבד. הממשק יציין את סוג התמיכה הזה. הייצוג והמרחק הם חלק מן ההגדרה, ולכן רדיוס מועתק בין ייצוגים רק כבחירה מפורשת של המשתמש.

## אנליזת OOF

השיטה מאמנת מסווג על חלק מן הדאטה ומפיקה לכל דגימה חיזוי רק כשהיא בחלק הבדיקה. בכל חזרה כל דגימה מופיעה בחלק הבדיקה פעם אחת. חזרות נוספות משתמשות בחלוקות וב־seeds מתועדים; אין להעביר חלוקות חוזרות ישירות למסלול שמניח חיזוי יחיד לדגימה.

ברירת המחדל תהיה מסווג לוגיסטי, חמישה folds ושלוש חזרות. ניתן להעביר estimator תואם או רכיב מודל רשום. בהיעדר groups תתבצע חלוקה stratified; כאשר groups קיימים תיבחר חלוקה קבוצתית עם ניסיון לשמר התפלגות קטגוריות.

המסווג צריך להחזיר predict_proba או להשתמש ב־adapter מפורש שמפיק class evidence. שמות הקטגוריות מיושרים לפי classes של כל מודל, ולא לפי מיקום עמודה משוער. לפני הריצה נבדק שכל חלק אימון מכיל את הקטגוריות הדרושות ושמספר הדגימות והקבוצות מאפשר את החלוקה. כשל אינו מטופל באמצעות המצאת הסתברות אפס לקטגוריה חסרה.

ההסתברויות מחזרות תקינות ימוצעו לכל דגימה לצורך הציון הראשי. במקביל יישמרו תוצאות כל חזרה, מספר החיזויים התקינים והפיזור ביניהם. ברירת המחדל לדרישת כיסוי היא חיזוי תקין אחד לכל חזרה מתוכננת, ולדרישת האימון לפחות שתי דגימות מכל קטגוריה בכל קבוצת אימון. ניתן לשנות דרישות אלה במפורש. אם משתמשים בכוונון hyperparameters, גם הוא מתבצע בתוך חלק האימון. ציוני OOF מתארים את מסווגי הבדיקה שנבחרו; המוצר אינו תלוי במסווג המוצר של המשתמש.

# 8 משמעות הציונים התמיכה והיציבות

## class evidence והציונים המובנים

שתי השיטות הראשונות מפיקות לכל דגימה וקטור q של עדויות לקטגוריות, עם ערכים אי שליליים שסכומם אחד. בשכנים זהו שיעור משקל השכנים של כל קטגוריה, וב־OOF זהו ממוצע ציוני הקטגוריות מן החיזויים התקינים. מקור העדות והנחותיו נשמרים.

לגרסה הראשונה יוגדרו ציוני הדירוג המובנים באמצעות כללי החישוב הבאים:

```python
alternative = max(
    (c for c in classes if c != original_label),
    key=lambda c: q[c],
)
label_issue_score = max(
    0.0, q[alternative] - q[original_label]
)
pair_overlap = 2.0 * min(q[class_a], q[class_b])
```

חפיפה זוגית גבוהה דורשת עדות לשתי הקטגוריות. הציון הכולל של חפיפה הוא הציון של שתי הקטגוריות בעלות העדות הגבוהה ביותר. פירוט חפיפה מול התיוג המקורי מחושב בנפרד לכל חלופה רלוונטית. כך ניתן לתאר גם דגימה שמסומנת A אך נראית מעורבת בין B לבין C.

בטבלת overlaps יישמרו כברירת מחדל זוגות הכוללים את התיוג המקורי, ובנוסף זוג הקטגוריות המוביל אם הוא שונה. כל זוג בהיקף זה יישמר גם אם ציונו אפס. זוג שאינו בהיקף אינו תוצאה מחושבת. אין חובה לייצר את כל זוגות הקטגוריות בריבוע. בשוויון תהיה בחירה דטרמיניסטית לפי סדר קטגוריות מתועד.

| התיוג המקורי | עדויות לדוגמה | פירוש |
|---|---|---|
| A | A 0.95 וגם B 0.05 | התאמה לתיוג המקורי |
| A | A 0.50 וגם B 0.50 | חפיפה גבוהה בלי עדיפות חזקה לחלופה |
| A | A 0.05 וגם B 0.95 | חשד חזק יותר לתיוג שגוי וחפיפה נמוכה |
| A | A 0.05 וגם B 0.475 וגם C 0.475 | חשד לתיוג וחפיפה בין חלופות יכולים להתקיים יחד |

הציונים נמצאים בטווח 0 עד 1 לצורכי דירוג. הם אינם הסתברות שהתיוג שגוי, וגם אינם נעשים בני השוואה בין שיטות רק משום שיש להם אותו טווח. שיטה מותאמת רשאית להפיק ציון אחר, תוך תיאור כיוון, טווח ומשמעות; שדות שאינם רלוונטיים נשארים חסרים. בשלב הראשון נשמרת התפלגות הקטגוריות שנצפתה, ללא תיקון priors אוטומטי. סיכומים יציגו גם פילוח לפי קטגוריה כדי לחשוף השפעות של חוסר איזון.

## תמיכה

התמיכה תיוצג באמצעות מדדים מספריים ובאמצעות sufficient_support שנגזר מכללים מתועדים של כל שיטה. השדה יכול להיות True, False או חסר כאשר השיטה אינה מסוגלת להעריך תמיכה. יישמר גם support_kind, כגון local_neighbors או prediction_coverage.

בשכנים יישמרו מספר השכנים שנבחרו, מרחק קרוב ביותר, מרחק מרבי וחציוני, רדיוס ששימש, כמות קבוצות ייחוס אם זמינה ומספר שכנים אפקטיבי. בחישוב משוקלל:

```python
effective_neighbors = weights.sum() ** 2 / (weights ** 2).sum()
```

המדד מתאר ריכוז משקל, ואינו הופך שכנים מתואמים לדגימות בלתי תלויות. כאשר אין שכנים, הוא חסר והתמיכה אינה מספקת. במקרה של שקלול לפי מרחק משתמשים ב־epsilon מתועד.

ב־OOF התמיכה המובנית מתייחסת לכיסוי חיזויים תקינים ולכמות נתוני האימון לכל קטגוריה. חיזוי חד אינו משמש הוכחה לתמיכה מקומית. מידע על צפיפות מקומית יכול להתווסף באמצעות רכיב נפרד, בלי להכניס תלות חובה בשיטת השכנים.

## יציבות

יציבות היא תוצאה של ניסוי מוגדר: שינוי חלוקות OOF, seed או דגימת ייחוס. השיטה תחזיר כאשר ניתן את שיעור ההסכמה על החלופה, סטיית התקן של הציונים ומספר החזרות התקינות. סוג השינוי והיקפו נשמרים במטא־דאטה.

# 9 כללי החלטה וכיול

החלטה היא שכבה שמקבלת ציונים ומדדים שכבר חושבו ומחזירה דגלים. לשתי מטרות הבדיקה יהיו דגלים עצמאיים: label_issue ו־overlap. תיתכן הפעלה של שניהם. הדגלים אינם מחליפים את הציונים הרציפים.

שינוי סף תצוגה או החלטה מפעיל מחדש רק את המדיניות. שינוי בייצוג, מרחק, רדיוס, מספר שכנים או חלוקת folds מחייב אנליזה מחדש. כיול רדיוס משתמש בנתוני ייחוס מתאימים; כיול סף איכותי על תיוגים שנבדקו ידנית הוא תהליך נפרד, עם תיעוד קבוצת הכיול. אין לבצע כיול של ספים על חלק בדיקה ולהציג אחר כך את אותה קבוצה כאימות בלתי תלוי.

# 10 חוזה התוצאות

## אובייקט התוצאה

AuditResult הוא אובייקט Python עם שדות מפורשים. טבלאותיו הן pandas DataFrames רגילים. אין subclass של DataFrame בעל התנהגות נסתרת. הריצה שומרת run_id, dataset_id, schema_version וסטטוס ביצוע.

| שדה או פעולה | תוכן |
|---|---|
| samples | שורה לכל sample_id ו־method_id |
| overlaps | זוגות קטגוריות וציוני חפיפה לכל דגימה ושיטה |
| class_evidence | עדות לכל קטגוריה עם מקור העדות |
| diagnostics | מדדים נוספים של תמיכה ויציבות |
| representations | ייצוגים וקואורדינטות עם scope של ה־fit |
| data | קלט הריצה וה־metadata שנבחר |
| evidence | גישה לראיות לפי מזהי דגימה ושיטה |
| run_info | הגדרות בפועל, רכיבים, חלוקות, גרסאות ו־seeds |
| apply_policy | יצירת DecisionResult בלי חישוב אנליזה מחדש |
| export_csv | ייצוא טבלה או חבילת טבלאות |
| save | שמירת ריצה שלמה לצורך פתיחה חוזרת |

samples יכלול sample_id, method_id, original_label, label_issue_score, alternative_label, max_overlap_score, overlap_class_a, overlap_class_b, sufficient_support, support_kind ו־status. לכל ציון סטנדרטי שמקורו אינו מובן מאליו יישמר מזהה הגדרת הציון.

diagnostics יהיה בפורמט ארוך עם sample_id, method_id, metric_name, numeric_value או text_value. כך מדדים ייחודיים לשיטה אינם מחייבים שינוי schema מרכזי. ה־UI יכול להצמיד מדדים נבחרים כעמודות בטבלה המרכזית.

## ראיות ונתונים חסרים

טבלת שכנים תכלול query_sample_id, neighbor_sample_id, rank, distance, weight ותיוג השכן. טבלת OOF תכלול sample_id, repeat_id, fold_id, class_label ו־class_score. פרטי המודל והחלוקה נשמרים עם הריצה, בלי לחייב שמירת מודלים מאומנים.

כל שיטה שהסתיימה בהצלחה מחזירה שורה לכל דגימה שהתבקשה. דילוג נקודתי מחייב status וסיבה. שגיאה בשיטה יכולה להפיק ריצה partial כאשר המשתמש בחר להמשיך; שורות method_failed מזוהות והציונים בהן חסרים. אין להשמיט דגימות או להמציא ציונים. כשניתן לחשב ציון אך התמיכה נמוכה, הציון הגולמי יכול להישמר לצד מצב התמיכה; המדיניות קובעת אם להימנע מהכרעה.

DecisionResult מכיל policy_id, score_run_id, method_id וטבלת דגלים לפי sample_id. טבלת סקירה אנושית יכולה לשמור אישור, דחייה, תיוג מוצע והערה לצד מזהי הריצה והדגימה. היא אינה משנה את snapshot הקלט של תוצאה קיימת.

## ייצוגים לתצוגה

כל ייצוג שומר feature_names, sample_ids, fitted_scope, תצורת רכיב ו־seed. קואורדינטות מ־folds שונים אינן מחוברות כאילו נלמדו במערכת צירים אחת. עבור UI של ריצת OOF אפשר ללמוד ייצוג reference נוסף על כלל הדאטה, ולסמן אותו כתצוגה בלבד. הוא אינו משמש ליצירת חיזויי OOF.

# 12 טעינת קבצים וייצוא דרך הממשק

## טעינת נתוני מקור

ה־UI יספק העלאת CSV או Excel מן המחשב, ללא צורך בכתיבת קוד או בהכנת DataFrame. ב־CSV יהיו תצוגה מקדימה ובחירת delimiter, encoding ושורת כותרת. ברירת המחדל תהיה UTF 8, עם תמיכה ב־BOM. ב־Excel תהיה תמיכה ב־`.xlsx` וב־`.xls`, בחירת גיליון ושורת כותרת ותצוגה מקדימה של הגיליון שנבחר. קובץ בעל כמה גיליונות יחייב בחירה מפורשת של גיליון אחד; אין איחוד אוטומטי.

לאחר תצוגה מקדימה, שני המסלולים ימשיכו לאותו מסך לבחירת עמודת תיוג, עמודת מזהה אופציונלית, פיצ׳רים, groups ו־metadata. מסך הטעינה לא יכלול חיבור SQL או אפשרויות ייבוא לפורמטים נוספים.

מזהים טקסטואליים ייטענו באופן ששומר אפסים מובילים. ב־Excel נדרש שהמזהה יישמר בתא כטקסט אם לאפסים יש משמעות; עיצוב תצוגה של מספר, כגון 00123, אינו מקור אמין לזהות הטקסטואלית. טיפוסים שהוסקו יוצגו בתצוגה המקדימה, והמשתמש יוכל להגדיר טיפוס עמודה במפורש. המרה נוספת של טקסט למספר תתבצע רק עבור עמודות שנבחרו כמספריות. שגיאת המרה תציג שם עמודה, מספר שורת מקור ודוגמת ערך, וב־Excel גם את שם הגיליון. שמות כפולים, מזהים כפולים, תיוגים ריקים ושורות לא תקינות לא יתוקנו באופן סמוי. בהיעדר מזהים ייווצרו מזהים שמלווים את ה־snapshot ונכללים בכל ייצוא.

הייבוא יקרא ערכים מגיליון Excel ללא חישוב נוסחאות. כשנדרשים ערכי נוסחה ייקראו הערכים המחושבים השמורים בקובץ; תא ללא ערך שמור יטופל כחסר ויוצג באבחון. אין למלא מזהים או ערכים חסרים מתוך תאים ממוזגים באופן סמוי.

טעינה דרך ה־UI תפעיל את אותם קוראים, מיפוי ואימות שבהם משתמשים בקוד. הגדרות הטעינה, שם הגיליון כשישנו ושורת הכותרת יישמרו עם הריצה לצורך שחזור ואבחון. ייבוא CSV ו־Excel הוא חלק מהספרייה ואינו תלוי בתלויות UI.

## ייצוא תוצאות

המשתמש יוכל לבחור לייצא את כל תוצאות הריצה, את התוצאות המסוננות או את הדגימות שנבחרו. האפשרות הפעילה ומספר השורות יוצגו לפני ההורדה. הייצוא העיקרי יהיה CSV של טבלת הממצאים, הכולל sample_id, method_id, תיוגים, ציונים, מדדי תמיכה נבחרים וסטטוס. אפשר לצרף דגלים, פיצ׳רים ו־metadata באמצעות בחירה מפורשת.

## שמירת ריצה ופתיחתה

CSV מסכם לבדו אינו שומר את כל המידע הדרוש לפתיחת חקירה מלאה. לכן תהיה פעולה נפרדת לשמירת קובץ `.audit.zip` שכולל טבלאות, snapshot נתונים, ייצוגים זמינים ו־manifest שנוצר אוטומטית. ה־manifest ישמור schema, טיפוסים, IDs, סדר עמודות, רכיבים, הגדרות ו־provenance.

פתיחת קובץ כזה תשחזר תצוגה ללא fit או התקנת הרחבות. הרצה מחדש של הרחבה מותאמת דורשת שהקוד המתאים יהיה זמין; לצורך צפייה נדרשים רק הנתונים והתוצאות. אין צורך לערוך את ה־manifest, ואין לטעון ממנו אובייקטי קוד או pickle.

אם המשתמש בוחר להשמיט את נתוני המקור מן החבילה, המסך יסביר אילו תצוגות לא יהיו זמינות בפתיחה חוזרת. טעינת CSV או Excel של מקור ופתיחת ריצה שמורה יהיו פעולות מובחנות. שמירת ריצה מלאה ופתיחתה ישמרו מזהים, טיפוסי תיוג, ציונים ומדיניות; CSV רגיל אינו מבטיח שחזור מלא של כל טיפוסי pandas. ייצוא התוצאות נשאר CSV; ייצוא ל־Excel אינו דרישה לגרסה הראשונה.

# 13 הפעלה אוטומטית והפצה

## מסלולי הפעלה

ההפצה תספק קובץ הרצה מרכזי `run_ui.py`, יחד עם `run_ui.cmd` עבור Windows ו־`run_ui.sh` עבור מערכות POSIX. קבצי המעטפת מפנים לאותו bootstrap ואינם משכפלים את לוגיקת ההתקנה. לאחר התקנת החבילה תעמוד גם הפקודה `data-audit ui`. אפשרויות שורת הפקודה הבסיסיות יהיו `--offline`, `--no-browser` ו־`--port`; כולן אופציונליות, והמסלול הרגיל אינו דורש ארגומנטים.

תנאי הקדם לגרסת המקור הוא Python נתמך שכבר מותקן. טווח התמיכה הראשוני המתוכנן הוא Python 3.11 עד 3.13, בכפוף למטריצת בדיקות התלויות. ה־launcher יכין את יתר סביבת ה־UI אוטומטית. בהיעדר Python מתאים תופיע הודעה ממוקדת עם הפעולה הנדרשת. הפצה הכוללת runtime ואינה דורשת Python מותקן היא הרחבת הפצה עתידית.

## פעולות קובץ ההרצה

1. לזהות מערכת הפעלה, Python נתמך ונתיבי התקנה, גם כשהרצה נעשית מתיקיית עבודה אחרת.
2. ליצור סביבת venv ייעודית למוצר או להשתמש בסביבה קיימת המתאימה לגרסתו.
3. להתקין את החבילה ואת תוספת UI לפי גרסאות שנבדקו. אין לשנות סביבת Python של פרויקט אחר או לדרוש הרשאת מנהל.
4. לגלות הרחבות מן הנתיבים שהוגדרו למוצר ולבצע בדיקת תקינות קצרה.
5. לבחור פורט מקומי פנוי ולהפעיל תהליך UI אחד. בגרסה הראשונה ייפתח חיבור localhost בלבד.
6. להמתין לסימן מוכנות מהשרת, לפתוח דפדפן ולהציג כתובת ולוג במקרה שהדפדפן אינו נפתח.
7. לאפשר עצירה מסודרת ולסגור תהליכי ילד שה־launcher יצר.

לא יידרשו פקודות נפרדות ל־backend ול־frontend, בניית נכסי web ידנית או עריכת קובץ הגדרות. רשת נדרשת להתקנה הראשונה כאשר התלויות אינן זמינות מקומית. הרצה לאחר הכנה לא תדרוש רשת; מצב offline יאפשר שימוש במאגר wheels שסופק מראש ויחזיר אבחון ברור כשחסרה תלות. שינוי גרסה או תיקון סביבה יטופלו בתוך סביבת המוצר, תוך שמירה על תוצאות והרחבות.

## הבחירה הטכנית הראשונית

ה־UI הראשוני ימומש ב־Streamlit עם Plotly לגרפים, כדי לשמור על בסיס קוד פייתוני ועל תהליך הפעלה אחד. זו בחירת שכבת תצוגה, לא תלות של הליבה. תכנון ה־API, הטבלאות והסכמות אינו מסתמך על Streamlit.

הפצה כ־wheel תכלול ליבה ותוספת `ui`; תוספת `ae` תכיל את תלויות ה־autoencoder. קוראי CSV ו־Excel ייכללו בהתקנת הליבה: pandas לקריאה טבלאית, openpyxl עבור `.xlsx` ו־xlrd עבור `.xls`, בגרסאות שייבדקו יחד. אין צורך להתקין את תוספת UI כדי לייבא קבצים. תלויות חיבור למסדי נתונים לא ייכללו כעת. הוספת extra אינה משנה את ה־API. גרסאות התלויות ייבדקו ויינעלו להפצת UI, בלי לחייב את משתמש הספרייה לשכפל סביבת פיתוח שלמה.

# 15 ריצה תפעולית ביצועים ושחזור

## מצבי ריצה ושגיאות

הריצה תתקדם דרך queued, running, completed, partial, failed או cancelled. התקדמות תימסר באירועים של הספרייה, לפי שיטה ושלב; רכיב מותאם אינו חייב לממש progress כדי לפעול. כשל רכיב יוצג עם שם, פרמטרים רלוונטיים וסיבה. traceback זמין בלוג הטכני.

הממשק יישאר מגיב בזמן fit וחיפוש שכנים. ביטול יהיה שיתופי בין יחידות עבודה; פעולה חיצונית שלא תומכת בביטול תסתיים ביחידה הנוכחית לפני עצירה. תוצאות חלקיות יסומנו במפורש. כל ריצה משתמשת ב־snapshot של הגדרותיה, ושינוי טופס בזמן ריצה לא ישנה אותה.

datasets בעלי קטגוריה אחת אינם מפעילים את ציוני התיוג והחפיפה המובנים. מספר דגימות קטן מ־k, קבוצת ייחוס ריקה, יותר רכיבי PCA מן האפשרי, שונות אפס וקטגוריות נדירות ב־folds מחייבים בדיקה מפורשת. כאשר יש פחות מ־k שכנים זמינים משתמשים במספר הזמין ומדווחים אותו; אין לשנות אוטומטית את min_neighbors. שדות מספריים בוליאניים, תיוגים ועמודות metadata אינם עוברים קידוד חדש בלי תיעוד המיפוי. טבלת קטגוריות פנימית תשמור את ערכי התיוג המקוריים ואת סדרם.

## שימוש בזיכרון ובתצוגה

טבלאות יוצגו באמצעות pagination או virtualization. אם הגרף מציג מדגם לצורך ביצועים, תופיע הודעה על מספר הנקודות המוצגות והדרך שבה נבחרו. האנליזה והייצוא ימשיכו להתייחס לאוכלוסייה שהוגדרה.

חיפוש שכנים יעבוד באצוות ולא יחייב מטריצת מרחקים בגודל מספר הדגימות בריבוע בזיכרון. אפשר להגביל פירוט evidence באמצעות הגדרה מפורשת; כאשר ראיות לא נשמרו, הדבר יסומן ולא יוצג כאילו הן זמינות. בגרסה הראשונה אין צורך במערכת caching מבוזרת.

## שחזור ו־cache

run_info ישמור רשימת פיצ׳רים וסדרם, fingerprint של הנתונים, IDs, הגדרות אפקטיביות, גרסאות חבילות ורכיבים, hash להרחבות מקומיות, seeds וחלוקות אימון ובדיקה. שחזור מובטח ביחס לאותה סביבה ובטולרנס מספרי מתועד; חישובי GPU ורכיבים חיצוניים יכולים להגביל דטרמיניזם.

אם ממומש cache, מפתחו יכלול גם את זהות נתוני ה־fit ואת גבולות ה־fold. אין לשתף ייצוג מאומן בין folds רק משום שיש לו אותם פרמטרים. תוצאה מחושבת נשמרת בנפרד ממצב הבחירה והסינון של UI.

## יעדי בדיקה מוצעים

יעדי התגובה ייבדקו על מחשב CPU בעל 8 ליבות ו־16GB RAM, וידווחו עם נתוני benchmark. היעד לפתיחה לאחר הכנה הוא עד 10 שניות; לסינון טבלת 100 אלף שורות תוצאה עד 2 שניות; ולצביעה או בחירה בגרף של עד 20 אלף נקודות עד 2 שניות. אלה יעדי קבלה מוצעים ולא מדידות של מימוש קיים.

זמן האנליזה יימדד וידווח בנפרד על 10 אלף דגימות עם 50 פיצ׳רים וחמש קטגוריות, לכל שיטה ולרכיבים אופציונליים. אין התחייבות לזמן קבוע עבור פונקציית משתמש או מודל שרירותי. ה־UI יציג התקדמות ויאפשר ביטול ללא תלות במשך הכולל.

# 17 שלבי המימוש ומדדי הצלחה

## סדר המימוש

- שלב ראשון: חוזי נתונים ותוצאות, API ציבורי, binding וגילוי הרחבות. מימוש דוגמאות חיצוניות ובדיקות עצמאות הליבה.
- שלב שני: סטנדרטיזציה, PCA, מרחק, שכנים, OOF, ציונים, מדיניות החלטה וראיות. הוספת autoencoder כתלות אופציונלית.
- שלב שלישי: קוראי CSV ו־Excel בספרייה וב־UI, ייצוא CSV, שמירת ריצה ופתיחתה, UI עם טפסים כלליים, טבלה, גרף ותחקור דגימה.
- שלב רביעי: launcher, התקנה נקייה, offline, ביצועים ותרחיש קבלה מלא מתחילת טעינה ועד ייצוא.

כל השלבים נדרשים לגרסה המתוארת. תמיכה במסדי נתונים וב־SQL, פורמטי קלט נוספים, הפצת runtime ארוז ושרת מרובה משתמשים נדחים להמשך התפתחות המוצר. הוספת קוראים בעתיד תיעשה בשכבת io ותשמור על חוזה ה־DataFrame ועל עצמאות הליבה מה־UI. השוואת ריצות עשירה ועריכת תיוגים קבוצתית יכולות להתרחב לאחר קבלת זרימת העבודה הבסיסית.

## מדדי הצלחה

הצלחת התשתית תימדד במספר המקומות שיש לשנות בעת הוספת הרחבה, בזמן עד הרצה ראשונה ובכמות קוד החיבור. רכיב בעל פרמטרים נתמכים לא ידרוש שינוי בליבה, ב־UI או בפורמט ייצוא קיים.

הצלחת המוצר תימדד בזמן עד ממצא שניתן לבדיקה, בשיעור הממצאים שאנליסט מאשר מתוך הדגימות שנסקרו ובשימוש בראיות לצורך החלטה. מדדים אלה ייאספו בניסוי משתמשים מתועד. דיוק לזיהוי תיוג שגוי יוערך רק מול קבוצת דגימות שנבדקה באופן עצמאי, עם פילוח לפי קטגוריה ושיטה.

# 18 מקורות טכניים

המקורות הבאים משמשים לביסוס מנגנוני המימוש. הגדרות המוצר, ברירות המחדל ויעדי הקבלה נקבעים במסמך ואינם מוצגים כתקן של הספריות המצוטטות.

- pandas DataFrame לתיאור המבנה הטבלאי והצירים המסומנים: https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.html
- pandas read_csv לקריאת CSV והגדרות טיפוסים: https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html
- pandas read_excel לקריאת גיליונות, מנועי Excel וטיפוסים: https://pandas.pydata.org/docs/reference/api/pandas.read_excel.html
- Python inspect לקריאת חתימות: https://docs.python.org/3/library/inspect.html
- scikit learn בנושא הפרדת fit ו־transform ומניעת זליגת מידע: https://scikit-learn.org/stable/common_pitfalls.html
- scikit learn בנושא חיזויים מחוץ לחלק האימון: https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.cross_val_predict.html
- Python Packaging להגדרת חבילה ותלויות אופציונליות: https://packaging.python.org/en/latest/guides/writing-pyproject-toml/
- Python venv לבידוד סביבת ההפעלה: https://docs.python.org/3/library/venv.html
- Streamlit DataFrame לתצוגת טבלאות ובחירה: https://docs.streamlit.io/develop/api-reference/data/st.dataframe
